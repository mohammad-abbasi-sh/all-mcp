# all-mcp — یک MCP برای همه

**یک سرور MCP که هر ۶۰ سرور MCP محمد عباسی را در خود دارد — ترکیه (۳۲)، آلمان (۲۷)، بن‌باما (۱) — ۳۲۴ ابزار با یک ورودی در کانفیگ. هر سؤالی بپرسید؛ خودش به MCP درست وصل می‌شود.**

به فارسی، ترکی، آلمانی یا انگلیسی بپرسید:

> «قیمت بلیط قطار از برلین به مونیخ چقدره؟»
> ← ابزار `flixtrain_search_trains` را پیدا می‌کند، صدا می‌زند و حرکت‌ها و قیمت‌های واقعی را برمی‌گرداند.

> «قیمت اتوبوس مونیخ به هامبورگ»
> ← به حمل‌ونقل **آلمان** می‌رود، نه ترکیه — چون سؤال نام شهرهای آلمان را برده است.

## واقعاً چطور کار می‌کند (صادقانه)

داخل این سرور هیچ تشخیص جادویی نیست. به‌صورت پیش‌فرض، هوش مصنوعی خودتان — Claude Desktop، Claude Code، Cursor — تشخیص می‌دهد:

1. **`search_tools(query)`** — جست‌وجوی کلیدواژه‌ای روی همهٔ ۳۲۴ ابزار به هر چهار زبان، مرتب‌شده بر اساس تطابق موضوعی، تطابق مکانی (شهرها/کشورهای نام‌برده در سؤال) و موقعیت ذخیره‌شدهٔ شما. بهترین ابزارها را با سرور، کشور و توضیح یک‌خطی برمی‌گرداند.
2. **`call_tool(server, tool, arguments)`** — ابزار انتخاب‌شده را روی سرور فرزند درست اجرا می‌کند (با `uvx` در لحظه ساخته می‌شود) و نتیجهٔ واقعی را برمی‌گرداند.

نشان دادن هر ۳۲۴ ابزار به‌صورت هم‌زمان هر کلاینتی را غرق می‌کند (انفجار کانتکست، انتخاب اشتباه). پس روتر فقط ۶ ابزار دارد — همان الگوی استاندارد روتر:

| ابزار | کار |
|---|---|
| `search_tools(query, limit?)` | ابزارهای مرتب‌شده برای یک سؤال (هر زبان) |
| `call_tool(server, tool, arguments?, timeout?)` | اجرای یک ابزار روی یک سرور فرزند |
| `ask(question, location?)` | پاسخ یک‌مرحله‌ای: مسیریابی + اجرا + توضیح (بخش بعد) |
| `list_servers(catalog?, country?, category?)` | مرور ۶۰ سرور |
| `set_location(country, city?)` | ذخیرهٔ کشور شما برای مسیریابی موقعیت‌محور (فقط فایل محلی) |
| `meta_health()` | آمار ایندکس، وضعیت PyPI، uvx، موقعیت فعلی و ارائه‌دهندهٔ مسیریابی |

یک جست‌وجو + یک فراخوانی — بدون رفت‌وبرگشت اضافه. یا یک `ask` — بخش بعد.

## ‏`ask`‏: پاسخ یک‌مرحله‌ای (LLM مسیریابی اختیاری)

`ask(question)` در یک فراخوانی پاسخ می‌دهد: سؤال را به سرور+ابزار+آرگومان درست می‌رساند، اجرا می‌کند و نتیجه را با توضیح یک‌خطی مسیریابی، گزینه‌های جایگزین، رد مسیریابی (`steps`: یک ورودی برای هر تلاش مسیریابی/اجرا، `{server, tool, status, ms}`) و لینک‌های منبع (`sources`) برمی‌گرداند.

مسیریابی به یک LLM کوچک نیاز دارد. از **کلید خودتان** (یا مدل محلی) استفاده می‌کند — روتر هیچ کلیدی همراه ندارد و کلید شما هرگز جز به ارائه‌دهنده‌ای که انتخاب کرده‌اید از دستگاه خارج نمی‌شود:

| ارائه‌دهنده | متغیر محیطی | مدل پیش‌فرض | رایگان؟ |
|---|---|---|---|
| Gemini | `GEMINI_API_KEY` | `gemini-3.5-flash` | سطح رایگان در [AI Studio](https://aistudio.google.com) |
| OpenAI | `OPENAI_API_KEY` | `gpt-4o-mini` | پولی |
| Anthropic | `ANTHROPIC_API_KEY` | `claude-haiku-4-5` | پولی |
| OpenRouter | `OPENROUTER_API_KEY` | `nvidia/nemotron-3.5-lightning:free` | مدل‌های سطح رایگان — پیش‌فرض خوب بدون کلید پولی |
| Ollama (محلی) | — | `qwen2.5:7b` | کاملاً رایگان/محلی، بدون کلید |

انتخاب: متغیر `LLM_PROVIDER` ‏(`gemini` / `openai` / `anthropic` / `openrouter` / `ollama`)‏، وگرنه اولین ارائه‌دهندهٔ پیکربندی‌شده به همین ترتیب. Ollama فقط وقتی صریحاً انتخاب شود استفاده می‌شود (`LLM_PROVIDER=ollama`، هاست پیش‌فرض `http://localhost:11434`؛ اول `ollama pull qwen2.5:7b`). تغییر مدل: `ALL_MCP_<PROVIDER>_MODEL` (مثلاً `ALL_MCP_GEMINI_MODEL`).

**هیچ ارائه‌دهنده‌ای نیست؟** `ask` باز هم کار می‌کند: به بهترین نتیجهٔ جست‌وجو برمی‌گردد — اگر آرگومان لازم نداشته باشد خودکار اجرا می‌شود، وگرنه با فهرست پارامترهای لازم برگردانده می‌شود. `search_tools` + `call_tool` همیشه بدون هیچ کلیدی کار می‌کنند.

## پل HTTP: چت سایت

چت سایت با روتری که روی دستگاه خودتان اجرا می‌شود حرف می‌زند (پل محلی — باز هم بدون بک‌اند ما):

```bash
uvx all-mcp --http --port 8765
```

فقط localhost ‏(`127.0.0.1`)‏. اندپوینت‌ها:

| اندپوینت | بدنه | خروجی |
|---|---|---|
| `GET /api/health` | — | سرورها/ابزارهای ایندکس‌شده، پیکربندی LLM بله/خیر (هرگز خود کلید) |
| `POST /api/search` | `{"query", "limit"?}` | ابزارهای مرتب‌شده |
| `POST /api/call` | `{"server", "tool", "arguments"?}` | نتیجهٔ ابزار |
| `POST /api/ask` | `{"question", "location"?}` | پاسخ یک‌مرحله‌ای + `steps` + `sources` |

```bash
curl -X POST http://127.0.0.1:8765/api/ask \
  -H 'Content-Type: application/json' \
  -d '{"question": "قیمت بلیط قطار از برلین به مونیخ چقدره؟"}'
```

CORS فقط `https://mohammad-abbasi-sh.github.io` و مبدأهای `localhost` را می‌پذیرد. `/api/ask` یک راهنمای موقعیت اختیاری برای هر درخواست می‌پذیرد (`{"country": "DE", "city": "Berlin"}`) که چت از حافظهٔ مرورگر می‌فرستد — از موقعیت ذخیره‌شده قوی‌تر است، ولی نام مکان در خود سؤال باز هم برنده است. آرایهٔ `steps` در پاسخ همان رد زندهٔ مسیریابی است که چت متحرک نشان می‌دهد («در حال اتصال به flixtrain-mcp…») و `sources` لینک‌های استناد هستند.

## نصب (یک ورودی در کانفیگ)

به `uvx` نیاز است ([نصب uv](https://docs.astral.sh/uv/)). به کانفیگ Claude Desktop اضافه کنید (`claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "all-mcp": {
      "command": "uvx",
      "args": ["all-mcp"],
      "env": {
        "USER_COUNTRY": "DE"
      }
    }
  }
}
```

`USER_COUNTRY` اختیاری است (`DE` / `TR` / `IR`): به روتر می‌گوید کجا هستید تا سؤال مبهم بدون نام مکان، به سرویس‌های کشور شما برود. یک بار موقع نصب تنظیم می‌شود. بدون آن، از ابزار `set_location` استفاده کنید (فقط در `~/.config/all-mcp/location.json` روی دستگاه خودتان ذخیره می‌شود).

بعد فقط سؤال بپرسید. امتحان کنید: «هوای برلین چطوره؟»، «dollar exchange rate today»، «Fußball Ergebnisse Bundesliga»، «تخفیف گرگان».

## اولویت رتبه‌بندی

1. **نام مکان در خود سؤال برنده است.** «اتوبوس مونیخ به هامبورگ» حتی اگر موقعیت ذخیره‌شده ترکیه باشد، به آلمان می‌رود.
2. **راهنمای موقعیت هر درخواست از موقعیت ذخیره‌شده قوی‌تر است.** چت با هر `/api/ask` یک `{"country", "city?"}` از حافظهٔ مرورگر می‌فرستد (یا آرگومان `location` ابزار `ask`) — از `USER_COUNTRY`/`set_location` می‌برد، ولی باز به نام مکان در سؤال می‌بازد.
3. **موقعیت ذخیره‌شده تساوی را می‌شکند.** «قیمت بلیط اتوبوس» بدون نام مکان، با `USER_COUNTRY=DE` گزینه‌های آلمان را اول می‌آورد؛ با `TR` گزینه‌های ترکیه را.
4. **نه نشانه‌ای، نه موقعیتی:** گزینه‌های هر دو کشور مرتب‌شده برمی‌گردند — هوش مصنوعی شما از شما می‌پرسد منظورتان کدام کشور است، به‌جای حدس زدن.

هر نتیجهٔ جست‌وجو **کشور + توضیح یک‌خطی** سرور را دارد تا هوش مصنوعی خودش ابهام را رفع کند.

## حریم خصوصی

همه‌چیز **روی دستگاه خودتان** اجرا می‌شود: stdio، بدون بک‌اند، بدون حساب، بدون تله‌متری. برای جست‌وجو/فراخوانی هیچ کلید API لازم نیست. موقعیت شما (متغیر محیطی، فایل محلی یا راهنمای هر درخواست) هرگز از دستگاه خارج نمی‌شود. سرورهای فرزند متغیرهای سشن خودتان را به ارث می‌برند (بخش بعد) و هیچ‌چیز هرگز لاگ، چاپ یا ذخیره نمی‌شود. تنها فراخوانی شبکه‌ای خود روتر، فراخوانی مسیریابی `ask` است — و فقط وقتی ارائه‌دهنده‌ای پیکربندی کرده باشید: سؤال شما به همان ارائه‌دهنده می‌رود (یا با Ollama روی دستگاه می‌ماند) و کلید شما فقط در هدر درخواست به همان ارائه‌دهنده فرستاده می‌شود، هرگز لاگ یا ذخیره نمی‌شود.

## اکشن‌های حسابی (سشن‌ها)

دو سرور ابزار نوشتنی دارند که داخل حساب خودتان عمل می‌کنند (سبد خرید، علاقه‌مندی‌ها): `hepsiburada-mcp` و `migros-mcp`. آن‌ها از **کوکی سشن خودتان** استفاده می‌کنند که به‌صورت متغیر محیطی در کانفیگ MCP داده می‌شود — هرگز از دستگاه شما خارج نمی‌شود:

```json
"env": {
  "USER_COUNTRY": "DE",
  "HEPSIBURADA_SESSION": "your-session-cookie",
  "MIGROS_SESSION": "your-session-cookie"
}
```

اکشن‌های نوشتنی همیشه به `confirm=true` صریح در آرگومان‌ها نیاز دارند — سرورهای فرزند آن را اعمال می‌کنند و روتر بدون تغییر رد می‌کند. پرداخت هرگز خودکار نیست: ابزار سفارش فقط لینک پرداخت برمی‌گرداند و متوقف می‌شود.

## سرورهایی که هنوز روی PyPI نیستند (۶ عدد)

این سرورها در ایندکس هستند ولی پکیجشان هنوز منتشر نشده، پس `call_tool` به‌جای هنگ کردن، خطای واضح برمی‌گرداند: `paribu-mcp` ،`diyanet-mcp` ،`osym-mcp` ،`heise-mcp` ،`zeit-mcp` ،`welt-mcp`. به‌محض انتشار خودکار کار می‌کنند (ایندکس در هر اجرای فکتوری بازتولید می‌شود).

## سلسله‌مراتب

1. **all-mcp (این ریپو)** — مرجع اصلی: یک نقطهٔ ورود برای همه‌چیز.
2. **Turkey MCP و Germany MCP** — کاتالوگ‌ها و پلتفرم‌ها ([turkey-mcp](https://mohammad-abbasi-sh.github.io/turkey-mcp/)، [germany-mcp](https://mohammad-abbasi-sh.github.io/germany-mcp/)).
3. **ریپوهای تکی MCP** — یک ریپو برای هر سرویس.

هر سرور جدیدی که فکتوری روزانه اضافه می‌کند، این ایندکس را هم به‌روز می‌کند. ایندکس تولیدشده است، هرگز دستی نوشته نمی‌شود:

```bash
python3 gen_index.py            # بازتولید از کاتالوگ‌های محلی
python3 gen_index.py --probe    # به‌روزرسانی inputSchemaهای واقعی با uvx
```

`gen_index.py` برای کرون ساخته شده: غیرتعاملی، idempotent (اگر چیزی عوض نشده باشد، exit 0 و فایل دست‌نخورده می‌ماند)، نوشتن اتمیک و خلاصهٔ کوتاه در stdout.
